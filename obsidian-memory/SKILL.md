# Obsidian 记忆优先（每轮先查再答）

## 0. 本机配置（安装后先改这里）
把下面几项换成你自己的路径，只保留需要的，其余可以删掉：
- `VAULT`：Obsidian 库根目录，例如 `D:\Obsidian\MyVault`
- `PROFILE_DIR`：个人档案 / 偏好笔记所在目录（相对 VAULT，可选），例如 `Profile`
- `ARCHIVE_DIR`：历史对话归档目录（可选），例如 `Chats`
- `FALLBACK_MEMORY`：工作区里的记忆摘要文件（可选），例如 `MEMORY.md`

> 如果 `VAULT` 还是占位符，说明 skill 尚未配置：先向用户确认库路径，补全本段配置，再开始检索。

## 1. 库结构（按自己的库调整）
- `VAULT` 下通常有个人档案、目标、项目、学习笔记、日记 / 归档等目录；先 `glob` 看一眼命名，再决定读哪些。
- 优先读入口笔记（`00 首页.md`、`Home.md`、`README.md`、`MOC` 之类），建立目录感。
- 只读 `.md`；忽略 `.obsidian/`、`.trash/`、`_source/` 和附件目录。
- 归档 / 历史快照目录（文件名带归档日期、`archive`、`旧版` 等）只作补充，不当成现状；与主笔记冲突时以较新的主笔记为准。

## 2. 检索流程（用 agent 自带的 grep / glob / read，不用 shell）
1. **提关键词**：从消息里抽主题词（项目、课程、人物、目标、时间、专有名词），再做同义扩展（简称 / 全称 / 英文名 / 近义说法）。
2. **先读入口**：第一次检索时，先 `read` 入口笔记和 `PROFILE_DIR` 下的偏好笔记各 1 篇。
3. **grep 一次**：2~6 个关键词用 `|` 连成正则，限定 `VAULT`（或 `PROFILE_DIR`）下的 `*.md`；命中太少换同义词再搜一轮，仍无就用 `glob` 看目录命名。
4. **read 前 3~5 个最相关文件**：先看 frontmatter 的 `updated` / `created`，再看正文；长文用 offset/limit 分段读。
5. **判断相关性**：直接相关（必须用）/ 背景相关（用来调整语气、深度、优先级）/ 历史快照（只补充）/ 无关（跳过，不硬凑）。
6. **冲突处理**：以更新时间更晚的笔记为准；拿不准时在回答里说明“记忆里有两种说法，按较新的……”。
7. **成本控制**：最多 1~2 次 grep + 5 次 read；同一话题追问可复用上一轮结果，出现新关键词再查。

## 3. 整合回答
- 把记忆自然融进答案，别机械罗列；记忆影响的是结论、优先级、语气和例子。
- 引用时给来源和日期（如“按你 11-10 的《项目 X》笔记……”），区分“记录里的事实”和“我的推断”。
- 库里记了用户偏好的话，按偏好回答（语言、直接程度、讲解顺序等）。
- 敏感信息（财务、证件、账号、健康、家庭等）只在必要相关时提，不主动外扩。
- **没查到**：一句话说明“Obsidian 里没查到相关记录”，然后正常回答；绝不编造记忆。

## 4. 写回（有新信息才做）
- 消息带来新事实 / 新进展 / 偏好变化：更新 `PROFILE_DIR` 下对应主笔记（保留结构，更新 frontmatter `updated`），用 `[[双链]]` 关联相关笔记。
- 新项目 / 新目标：在对应目录新建笔记，并在入口 / 总览笔记里加链接。
- 不覆盖历史快照；不写账号密码 / 令牌；没有新信息就不写，避免每轮改库。

## 5. 隐私与安全
- 只读本地 Markdown，不上传任何内容；检索结果只用于本次回答。
- 不主动读取 `.obsidian/`、系统目录和附件二进制；不把库里的隐私内容带进群聊或第三方会话。
- 只用于用户本人的会话；面向群聊 / 其他机器人的 agent 不要加载本 skill。

## 6. 兜底
- 库路径不存在 / 不可读：用 `FALLBACK_MEMORY` 顶上，并在回答里说明“Obsidian 库暂时读不到”。
- 未配置：先向用户确认路径并补全第 0 节，再继续。
